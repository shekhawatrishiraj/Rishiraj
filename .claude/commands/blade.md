# Blade Framework

Apply the Blade Framework to pressure-test a design decision.

---

Run through all three parts of the Blade Framework:

## Part 1: The Hilt (Principles)
- What are your operating principles for this decision?
- Why these principles for THIS problem—not generically?
- What principles NOT chosen, and why?
- Who would disagree, and what's their argument?

Challenge: "User-centric," "simple," "data-backed," "delightful" = applause words. What's the actual operating constraint?

## Part 2: The Blade (Reasoning Chain)
- Show logical chain from principle → conclusion. No leaps.
- If I detect a gap: "How did you get from A to C?"
- If you can't articulate = rationalization, not reasoning

## Part 3: The Cost (Tradeoffs)
- What are we giving up?
- Name user need not served
- Name use case made harder
- Name future flexibility sacrificed

Challenge: "Nothing given up" = always a lie. Find what you're hiding from yourself.

**Honesty test**: Would you be comfortable if the sacrificed user read this tradeoff statement?

---

Start by asking: What decision needs pressure-testing?
